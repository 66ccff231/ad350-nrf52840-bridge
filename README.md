# XDS 功率计 → 标准 BLE 功率计 桥接固件（nRF52840）

把 XDS（喜德盛）功率计的私有蓝牙数据，转成一个**标准 BLE 功率计**广播出去，
让**行者 app** 和**行者小G+ 第三代**当作普通蓝牙功率计连接。

```
XDS 功率计 ---BLE 0x2A63---> 本固件（Central） ---BLE 0x1828 CPS---> 行者 app / 小G+ 3代
```

## 为什么不做 ANT+

| 方案 | 问题 |
|---|---|
| ANT+（S332 / S340） | Garmin/ANT 许可**明文禁止**在非 Nordic 原厂 nRF52 芯片上使用；第三方 ProMicro 板不在许可范围。且需注册审批 |
| **标准 BLE（本方案）** | 行者小G+ 第三代官方规格支持「**ANT+/蓝牙双连接，功率计均可连**」，行者官方也说明「非行者自有品牌传感器可搜到即连」。**免费、开源、无许可问题** |

## 已经确认的事实（有实测数据支撑）

| 项 | 结论 | 证据 |
|---|---|---|
| 通知负载长度 | **11 字节** | 实测 29 条通知全部 11 字节 |
| 偏移 6-7 = 踏频 | ✅ 确认 | 实测 `0x28`→40、`0x34`→52、`0x48`→72 rpm，精确吻合 |
| 偏移 8-9 = 曲柄角度 | ✅ 确认 | 实测 21°~339° 循环，符合曲柄旋转 |
| 偏移 0-1 = 总功率 | ⚠️ **未在真实负载下验证** | 实测空转时恒为 0（符合"无扭矩即无功率"），但缺真实骑行数据确认量纲 |
| 偏移 2-3 / 4-5 = 左右功率 | ⚠️ 未验证 | 同上 |
| 启动命令 `02 16 AA 10` | ❌ 你的设备不需要 | 写入 0x2A55 返回 `0x81` 拒绝，但不发也能收到数据 |

字段定义来自 [DuoDuoJuZi/xds_forwarding](https://github.com/DuoDuoJuZi/xds_forwarding) 的
`xds_protocol.c`。若日后拿到真实负载数据发现字段不符，只需改 `src/xds_protocol.c` 的偏移。

## 怎么编译（不需要本地装工具链）

用 GitHub Actions 云端编译，你本地什么都不用装：

1. 在 GitHub 上建一个新仓库
2. 把整个 `xds-nrf52840-bridge` 目录推上去
3. 推送后 Actions 自动构建
4. 构建完进 Actions 页面，下载 artifacts 里的 `xds-bridge-uf2`
5. 拿到 `zephyr.uf2`

**如果构建报 `board not found`**，改 `.github/workflows/build.yml` 里的 `-b` 参数：

| 你的板子 | 板名 |
|---|---|
| ProMicro / nice!nano 风格（推荐先试） | `promicro_nrf52840/nrf52840/uf2` |
| Nordic 官方开发板 | `nrf52840dk_nrf52840` |
| nice!nano v2 | `nice_nano_v2` |
| Nordic USB Dongle | `nrf52840dongle_nrf52840` |

## 怎么烧录

**UF2 引导器（最简单）**：
1. 双击开发板复位键，电脑上出现一个 U 盘
2. 把 `zephyr.uf2` 拖进去
3. 板子自动重启并开始工作

**注意**：如果你之前刷过别的固件（比如那个 516 字节的空壳 uf2），先确认引导器还正常
（双击复位能出现 U 盘）。刷不进就先 `Erase` 一次。

## 怎么用

1. 给板子上电
2. **踩一下功率计曲柄**唤醒它
3. 板上应开始闪烁/串口打印「已连接功率计」「已订阅 0x2A63」
4. 手机行者 app 或码表里搜蓝牙功率计，找 **XDS Power Bridge**
5. 连上后应能看到功率和踏频

**重要**：功率计同时只能被一个设备连接。用这个桥之前，
**必须关掉手机行者 app 里已有的传感器连接**，否则桥连不上功率计。

## 可能需要改的地方（首次编译/上机时）

| 症状 | 原因 | 怎么改 |
|---|---|---|
| 构建报找不到板子 | 板名不对 | 改 workflow 里的 `-b` 参数（见上表） |
| 编译报 `bt_le_scan_cb` 字段错误 | Zephyr 版本差异 | 删掉 `.timeout = NULL` 那行 |
| 编译报 `BT_GATT_CCC` 参数错误 | Zephyr 版本差异 | 参考你版本 Zephyr 的 `samples/bluetooth/peripheral_*` 写法 |
| 连上功率计但没数据 | 需要配对，或需要启动命令 | 见下面「已知未完成项」 |
| 码表搜不到 | 广播数据长度不足 | 确认 `CONFIG_BT_CTLR_ADV_DATA_LEN_MAX=31`，或缩短设备名 |

## 已知未完成项（我没做，说清楚）

1. **配对认证**：你最早的抓包里出现过 Passkey 配对帧（`d5013101`），
   说明功率计可能需要认证。本固件目前没有处理 `auth_passkey_display` /
   `auth_pairing_confirm` 回调。如果连上后拿不到数据，大概率是这里 ——
   需要补配对回调，可能还需要在串口里设置 Passkey。
2. **独立的启动命令发送**：`02 16 AA 10` 需要先发现 `0x2A55` 的句柄才能写。
   实测你的设备拒绝这条命令且不影响收数据，所以没实现。
3. **左右功率 / 踏频转发**：目前只转发总功率（CPS 最简形式 flags=0x0000）。
   想显示左右平衡需要扩展 flags 与可选字段。
4. **电池电压 / 状态指示**：没做。
